## Glossary

| Term | Definition |
|---|---|
| Acceptance criteria | Observable conditions used to determine whether a requirement or feature is complete. |
| API (Application Programming Interface) | A defined way for application components, such as the frontend and backend, to exchange requests and data. |
| Authentication | The process of verifying who a user or system is. |
| Authorization | The rules that determine which actions or data an authenticated user or system may access. |
| Backend | The server-side application that handles data, business rules, and services. |
| Business logic | Rules that govern how the application behaves and processes user actions or data. |
| Domain model | The main concepts in the product, their data, and the relationships between them. |
| Endpoint | A specific API operation, identified by an HTTP method and path, that clients can call. |
| Frontend | The part of the application users interact with, typically running in a web browser. |
| Idempotency | A property of an operation where repeating the same request does not cause unintended duplicate effects. |
| Non-goal | An explicitly excluded outcome or capability, used to keep the project scope clear. |
| User journey | The sequence of steps a user takes to achieve a goal using the product. |
